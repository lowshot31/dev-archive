# /ship — 릴리즈 엔지니어링

## Pre-flight 체크

### 1. 브랜치 상태 확인
```bash
git status
git branch --show-current
git log --oneline -5
```

### 2. main과 동기화
```bash
git fetch origin
git log --oneline origin/main..HEAD
```
main 이후 커밋이 있는지 확인. 없으면 "올릴 게 없다" 보고.

### 3. 충돌 사전 확인
// turbo
```bash
git diff --stat origin/main...HEAD
```

## 테스트 실행

### 4. 테스트 프레임워크 감지
프로젝트에 맞는 테스트 실행:
- `package.json`에 `test` 스크립트 → `npm test`
- `pytest.ini` 또는 `conftest.py` → `pytest`
- `go.mod` → `go test ./...`

### 5. 테스트 없으면?
테스트 프레임워크가 없으면 사용자에게 물어본다:
```
이 프로젝트에 테스트가 없습니다.

A) 테스트 프레임워크 설치하고 핵심 테스트 작성 (추천)
B) 테스트 없이 진행 (비추천)
```

**추천: 항상 A. 테스트 작성은 AI에게 가장 싸게 먹히는 작업이다.**

### 6. 커버리지 감사
테스트 결과 요약:
```
테스트: 42개 통과, 0개 실패
커버리지: 78% → 추가 필요한 영역: [구체적 파일]
```

## 커밋 & PR

### 7. 커밋 정리
Conventional Commits 형식으로 커밋이 정돈되어 있는지 확인:
- `feat:` / `fix:` / `chore:` / `docs:` / `test:`

### 8. PR 생성

브랜치를 push하고 PR 생성을 위한 정보를 정리:

```markdown
## PR 요약

### 변경사항
- [변경 1]
- [변경 2]

### 테스트
- [X] 단위 테스트 통과
- [X] 통합 테스트 통과
- [ ] E2E 테스트 (해당 시)

### 체크리스트
- [ ] 코드 리뷰 완료 (/review)
- [ ] 문서 업데이트 필요 여부 확인
- [ ] 브레이킹 체인지 없음
```

## Post-ship

### 9. 문서 업데이트
변경사항이 README나 API 문서에 영향을 주는지 확인.
필요하면 업데이트.

### 10. Ship 리포트

```
╔═══════════════════════════════════╗
║          SHIP REPORT              ║
╠═══════════════════════════════════╣
║ 브랜치:    feature/xxx            ║
║ 커밋:      N개                    ║
║ 파일:      +N / -N                ║
║ 테스트:    N 통과 / N 실패        ║
║ 커버리지:  N%                     ║
║ PR:        #NNN (또는 준비 완료)   ║
╠═══════════════════════════════════╣
║ 상태: SHIPPED / BLOCKED           ║
╚═══════════════════════════════════╝
```
